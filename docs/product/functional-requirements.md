## قواعد الكتالوج

- المعرّف `FR-NNN` فريد ولا يُعاد استخدامه؛ المتطلب الملغى يوسم `Withdrawn` ولا يُحذف.
- **حالة المتطلب:** `Draft` (غير معتمد تفصيلياً) · `Approved` (معايير القبول معتمدة) · `Deferred` · `Withdrawn`.
- **حالة التنفيذ** تُتتبَّع في GitHub Issues و[project/CURRENT_STATE.md](../../project/CURRENT_STATE.md) — وليس هنا.
- معايير القبول تُكتب بصيغة قابلة للاختبار، وتُعتمد في الـ Issue الخاص بالتنفيذ قبل البدء.
- يتحقق `scripts/validate/repo_checks.py` من عدم تكرار المعرّفات.

### FR-001 — المصادقة (User Authentication)

يجب أن يصل المستخدمون إلى المنصّة بعد مصادقة فقط.

- AC-1: لا يمكن الوصول لأي محادثة أو API دون جلسة مصادقة صالحة.
- AC-2 (عرض/M1): تسجيل محلي محمي مع إمكانية تعطيل التسجيل الذاتي العام.
- AC-3 (إنتاج/M6): الدخول عبر Microsoft Entra ID (OpenID Connect) باستخدام tenant الصندوق.
- AC-4 (إنتاج): تعطيل الدخول المحلي أو حصره بحسابات طوارئ موثقة.
- اعتماديات: D-05.

### FR-002 — محادثة متعددة النماذج (Multi-Model AI Chat)

- AC-1: يختار المستخدم النموذج من قائمة النماذج المعتمدة فقط.
- AC-2: تُعرض الاستجابات بشكل متدفق (streaming) ويمكن إيقافها.
- AC-3: لا تُعرض مفاتيح API للمستخدم بأي شكل.

### FR-003 — إدارة المحادثات (Conversation Management)

- AC-1: إنشاء، إعادة تسمية، بحث، وحذف المحادثات.
- AC-2: يرى المستخدم محادثاته فقط ما لم تتم مشاركتها صراحة.
- AC-3: سياسة الاحتفاظ تُطبَّق وفق OD-07 (TBD).

### FR-004 — مزوّدو نماذج خارجيون (External Model Providers)

- AC-1: إضافة مزوّد عبر الإعداد (configuration) دون تعديل الكود المصدري.
- AC-2: تُخزَّن بيانات الاعتماد كأسرار وقت التشغيل فقط (انظر [SECURITY.md](../../SECURITY.md)).
- AC-3: لا يُفعَّل أي مزوّد قبل اعتماده (OD-01).
- AC-4 (مستقبلي): توجيه مبني على سياسات (policy-based routing) حسب تصنيف البيانات.

### FR-005 — نماذج محلية (Local / Self-hosted LLMs)

- AC-1: ربط نقطة نهاية متوافقة مع OpenAI API (مثل vLLM أو Ollama) عبر الإعداد.
- AC-2: تبقى نقطة النهاية المحلية على شبكة خاصة غير مكشوفة للإنترنت.
- AC-3: متطلبات العتاد (GPU) **TBD**.

### FR-006 — تجربة عربية أولاً (Arabic-first Bilingual UX)

- AC-1: العربية لغة افتراضية للواجهة مع اتجاه RTL صحيح.
- AC-2: تبديل اللغة إلى الإنجليزية (LTR) دون فقدان الوظائف.
- AC-3: عرض صحيح للنصوص المختلطة (عربي/إنجليزي/كود) في المحادثة.
- AC-4: يتوافق مع [ux-standards.md](../design/ux-standards.md).

### FR-007 — رفع الملفات وتحليل المستندات (File Upload & Document Analysis)

- AC-1: أنواع الملفات وأحجامها المسموحة محددة في الإعداد.
- AC-2: الملفات المرفوعة تُخزَّن في تخزين دائم غير عام.
- AC-3: بيانات اصطناعية فقط حتى اعتماد البنية التحتية.

### FR-008 — المعرفة و RAG (Knowledge Management & RAG)

- AC-1: الإجابات المبنية على المعرفة تُظهر مصادرها.
- AC-2: صلاحيات الوصول للمعرفة تحترم صلاحيات المستخدم.
- AC-3: مسار إدخال المعرفة (ingestion) موثق مع مالك لكل مصدر معرفة.

### FR-009 — Artifacts

- AC-1: عرض المخرجات التفاعلية (HTML/React/Mermaid…) في بيئة معزولة (sandboxed).
- AC-2: يمكن تعطيلها بالإعداد إن لزم أمنياً.

### FR-010 — الوكلاء (Agents)

- AC-1: تعريف الوكيل (التعليمات، النموذج، الأدوات، المعرفة) له نسخة معتمدة في المستودع (`ai/agents/`).
- AC-2: آلية النشر من المستودع إلى LibreChat موثقة ومدعومة رسمياً (لا افتراض أن وضع ملف يكفي).
- AC-3: كشف الانحراف (drift) بين التعريف المعتمد والمنشور — انظر [ai/README.md](../../ai/README.md).

### FR-011 — المهارات (Skills)

- AC-1: المهارة لها تعريف معتمد في `ai/skills/` مع مالك ونسخة.
- AC-2: آلية الاستيراد في LibreChat يجب التحقق منها رسمياً قبل التنفيذ.

### FR-012 — MCP والأدوات (MCP Servers & Tools)

- AC-1: كل خادم MCP مسجَّل في قائمة معتمدة مع الصلاحيات والبيانات التي يصل إليها.
- AC-2: أسرار خوادم MCP لا تُكتب في المستودع.
- AC-3: صلاحيات الأدوات بأقل امتياز ممكن (least privilege).

### FR-013 — تنسيق سير العمل الوكيلي (Agentic Workflow Orchestration)

- AC-1: أي إجراء له أثر خارجي يتطلب تأكيداً بشرياً ما لم يُعتمد خلاف ذلك.
- AC-2: تفاصيل النطاق **TBD** (تحتاج تحليلاً عند الوصول إلى M5).

### FR-014 — التفويض والأدوار والإدارة (Authorization, RBAC & Administration)

- AC-1: فصل صلاحيات المسؤول عن المستخدم.
- AC-2: ربط الأدوار بمجموعات Entra ID (OD-03).
- AC-3: إتاحة الوكلاء/المساعدين حسب الدور.
- AC-4 (مقترح، #141): واجهة إدارة ويب يفتحها المسؤول من الجوال للمجموعات والأدوار المخصصة والمنح، يرفض غير المسؤولين، ولا تُغيّر
  إعدادات المنصة خارج Git ([ADR-0016](../architecture/adr/0016-librechat-admin-panel.md)).

### FR-015 — الهوية البصرية (Environment Fund Branding)

- AC-1: تطبيق الهوية عبر آليات LibreChat المدعومة أولاً ([ADR-0006](../architecture/adr/0006-upstream-first-customization.md)).
- AC-2: لا تُستخدم ألوان/خطوط/شعارات رسمية دون الأصول المعتمدة (D-04).
- AC-3: أي عنصر مؤقت موسوم "Provisional" في الإعداد والتوثيق.

### FR-016 — إطار المساعدين المتخصصين (Specialized Assistants Framework)

- AC-1: كل مساعد = تعريف وكيل + مهارات + معرفة + أدوات، بمالك أعمال ومعايير تقييم (evals).
- AC-2: أول مساعد مقترح: إعداد كراسات الشروط (RFP) — يحتاج اعتماد OD-06.

### FR-017 — التكامل مع تطبيقات الأعمال (Business Application Integration)

- AC-1: التكامل عبر عقود موثقة (OpenAPI أو MCP) في `integrations/` عند بدء العمل.
- AC-2: قائمة التطبيقات **TBD** (UR-03).
